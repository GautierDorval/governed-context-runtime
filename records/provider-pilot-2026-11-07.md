# Provider pilot implementation, 2026-11-07

This record describes the implementation candidate, not a production or scientific result. [English operation guide](../docs/en/provider-pilot.md) · [Guide français](../docs/fr/provider-pilot.md).

The owner authorized the 560-response campaign with Haiku 5.5, two distinct automatic judges (DeepSeek V3.2 on DeepInfra and Mistral Large 4), a shared USD 50 provider ceiling, production delivery and continuous Observatory monitoring. The implementation preserves the existing four-condition protocol and exact documentation inputs. Its transport and budget invariants were informed by InferensLab's separation of capture, spending authorization and accepted judgment; InferensLab's repository and experiments were not changed.

Local tests cover exact request bytes, completed empty/refusal/limited responses, partial transport failures, single eligible retries after the initial pass, conditional budget reservations, crash recovery, immutable input pins, rejected judgments, raw agreement and undefined kappa. A complete synthetic run retained 560 responses and 1120 annotations, with 1683 simulated sends including three preflights. It returned `SYNTHETIC_RUN`, not `RUN`.

The local Cloudflare workerd check found and corrected a Workflow serialization issue: the approved-input snapshot must be a plain object. It then exercised real local R2 conditional writes, Workflow registration, a simulated HTTP 429 with no platform retry, and the private aggregate status route. No real provider generation occurred in that check.

The package inventory explicitly admits the new provider, execution, budget, strict JSON, judging, campaign and Workflow modules, their declarations, tests, offline packet preparation script and bilingual guides. They use Web/Node built-ins and add no runtime dependency. Historical schema, verifier, fixture, protocol and previously tagged bytes remain unchanged.

At this implementation record, deployment, real model qualification and the actual campaign result remain separate evidence to be recorded against the final immutable artifact. The reusable plan stays `NOT_RUN`. Provider result records belong to a separately pinned private campaign, with public claims limited to verified aggregate findings. No general causal or architecture superiority claim is authorized by this pilot.

The Observatory candidate adds a 15-minute status monitor while preserving its natural daily collection. It reads existing operational evidence and the separately pinned private campaign status, retains private receipts and does not launch a collection, model request or historical recovery. Historical gaps and continuity remain reported; deployment alone cannot establish natural collection success. Access, active versions, bindings, cron and a naturally produced receipt require post-deployment verification.

The independent review identified a judgment-denominator error, ambiguous admission versus execution deadlines, insufficient judge timeouts, missing HTTP error digests, retryable invalid UTF-8, an unchecked serving/executing version relationship and a monitor receipt lost after a slow archive read. The correction separates technical-only trials from missing judgments, retains admission time, bounds later execution independently, gives judges five minutes with a preflight latency gate, strengthens error provenance and secret-echo filtering, and verifies execution identity. The Observatory reads the pilot aggregate after archive verification. Regression tests include failures and plausible mutations identified by the review; an initial review or local correction is not a final audit acceptance.

A separate deployment check established that the default Workflow subrequest quota cannot execute the full pilot. The delivery plan must configure and verify a 150000 allowance covering the bounded R2 and provider operations. The provider budget and attempt ceiling remain unchanged. The final audit must cover the corrected sources, regenerated artifacts, campaign pins and deployment plan together.

The corrected Workflow qualifies the actual bucket's create-only and etag conditions before provider calls. A durable budget-started marker prevents a missing ledger from silently resetting spending authorization. Native preflight timings determine and retain a latest scientific start time before the first trial. These gates stop safely on incomplete storage qualification, a lost ledger or insufficient execution time; local tests do not establish their production success.

## First native observations and recovery candidate

On November 7, the source `6eb244a5ac88fe81930a561ada04ec186550389d` was deployed as Worker `d0608f84-e097-4e9d-b10f-6582ed266224`. The first control-plane launch stopped before any step because the API preserved a JSON-string parameter as a string. Official Wrangler sends the parsed object. The corrected operator launch retained that failed instance and used the same campaign, manifest and budget; it did not change the executable.

At 22:06 UTC, native conditional R2 qualification passed and Haiku returned the required `OK`. DeepInfra returned a complete response, but the adapter rejected its optional `cache_write_tokens: null` usage field. The Workflow stopped before Mistral and before all 560 scientific trials. At that stop, the ledger retained USD 0.045730 as a conservative bound, including the full uncertain DeepInfra reservation. This is provider qualification evidence, not a scientific `RUN` or an invoice.

The recovery candidate accepts only DeepInfra's null or zero cache-write counter, while retaining total-token checks and refusing positive cache writes. Its explicit pinned amendment can revalidate the retained preflight bytes without resending them or reducing the uncertain reservation. Prior attempt records, original manifest, budget authorization, admission time and deadlines stay unchanged. A new execution identity names the corrected version, and both ledger and marker remain mandatory on replay. Unit tests and a local workerd run using the actual retained bytes accepted the recovered judgment, preserved the old records and stopped on the single simulated Mistral request. That local check made no real provider call. Deployment and continuation of this corrective candidate remain separate evidence.

The Observatory monitor produced its first natural receipt at 22:07 UTC on Worker `5c457ef1-7446-4352-a62a-1e2f0804ada5`. The authenticated status confirmed its 15-minute interval and current receipt. Both sources were fresh with verified archive and head integrity. The overall state remained degraded because collection continuity was 5/7 days despite 7/7 archived report days. The monitor did not trigger a producer collection or repair historical gaps.
