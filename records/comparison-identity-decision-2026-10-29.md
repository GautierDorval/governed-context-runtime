# Exact occurrences and pack comparison, 2026-10-29

Status: implementation decision for GCR-COMPARAISON-IDENTITE-20261029. No historical schema migration.

The comparator answers what differs in two explicitly selected, admitted states. A and B are roles chosen by the reader, not a declaration of publication succession. Versions are opaque strings; a corpus root identifies the snapshot, not the individual pack. Equality of versions or roots is never a substitute for inspecting the selected representation.

An occurrence is a repository-byte pack digest plus an escaped JSON Pointer, language, supported schema digest and snapshot resolution context. `/forbiddenInferences/1` locates only that occurrence in those bytes. Equal strings at different paths remain distinct. A rewrite of an unidentified list member is a removal and addition. Multiplicity and order are preserved. A calculated move is a possible structural transformation, not evidence of editorial history.

Existing object keys are admitted only within their named collection: causalContexts/id, applicabilityChains/id, weightingRules/ruleId, answerBoundaries/ruleId, includedUnits/unitId, includedArtifacts/path, selected units/unit.unitId and archived sources/sourcePath. Keys must be present and unique on each side. These keys permit structural matching in the same pack family, language and schema profile; they establish neither unchanged meaning nor universal persistence. Missing or duplicate keys refuse matching. Root, chain and causal lists retain separate paths.

Integrity verification reuses the pinned snapshot verifier. Full pack and manifest JSON Schema validation is a separate admission result. Historical schemas and recipes remain unchanged. Originals, parsed data, derived deltas and report presentation are separate. Strings, especially hashes and identifiers, remain atomic. No delta is applied to source data. All delta branches must normalize or fail; every operation must remain available in the report and rendered groups.

For the fictional Boreal fixture only, root boundary lists are generated from the chain lists. The comparator tests this declared relation separately and exposes both sides, including unchanged occurrences. linkedCausalContextId relates structures; it does not assert individual equivalence between forbidden_derivations and forbiddenInferences. Other source relationships are not inferred.

Future rule identities belong to the producer's authoritative source authoring process. The effective key is producer namespace plus opaque rule identifier, independent of text, index, pack and language. The producer explicitly decides whether an edit revises the same tracked requirement. A revision may change scope while retaining that logical identity. Unknown continuity stays unknown. New independent requirements, splits and merges receive new identifiers with attributed relations to exact predecessor revisions. Removed identifiers are never recycled; identical reintroduced text does not automatically revive an identity.

A future shared logical rule may have separate French and English formulation identities and revisions. A French revision neither edits nor certifies its English counterpart. Translation links are declarations requiring review, not semantic equivalence proofs. Independently governed linguistic requirements may instead have separate logical identities joined by an attributed translation relation.

Use existing content digests and occurrence references now. A future revision recipe must declare algorithm, canonicalization, Unicode treatment and exact covered fields before adoption. Retrospective correspondence tables remain separate, dated, attributed and reviewable, binding exact occurrences and method versions. They never rewrite archived packs or pretend to be original producer declarations. Publication succession likewise requires an attributed registry relation between exact states; it may branch and must reject cycles when defined as succession.

Rejected for this delivery: text similarity as identity, index-based rule identity, silent schema enrichment, duplicated manually maintained root lists, and a second verifier implementation. A future migration needs an explicit new schema edition, source producer changes, compiler/projection changes, reader/adaptor compatibility, historical coexistence, FR/EN revision tests and documentation. The present comparison does not depend on that migration.

Unspecified object collections match exact complete values only, with sorted object member names; a changed object is removed and added. This fallback is explicitly not an identity based on any incidental id field. Report pointers include the enclosing /pack, /manifest, /units or /sources context; /pack is removed when resolving a pointer inside original pack bytes.
