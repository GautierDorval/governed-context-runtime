# Provider pilot execution

[Français](../fr/provider-pilot.md) · [Scientific protocol](model-comparison.md)

The optional runner executes the existing `four-condition-pilot-3` protocol. It is separate from the hosted Runtime's pack transport and admission verifier. Adding this runner does not make the Runtime select intent, answer user questions or enforce model compliance.

The first approved configuration is Anthropic `claude-haiku-5-5` as respondent, DeepInfra `deepseek-ai/DeepSeek-V3.2` and Mistral `mistral-large-4-0` as distinct automatic judges. The shared provider budget is at most USD 50, including technical preflights and retries. This is a spending ceiling, not a quoted or observed cost. The frozen plan remains a reusable `NOT_RUN` template; a separate campaign result establishes an actual `RUN`. Injected test transports produce `SYNTHETIC_RUN` only.

## Request and response boundary

The respondent receives the exact assembled prompt as one user message, with a 512-token output ceiling and no tools, retrieval, system instruction or condition identifier. Documentation never becomes a system message. Haiku thinking is disabled and effort is medium; unsupported temperature, top-p and seed settings are omitted. Judges receive the actual prompt, received response and applicable rubric, without their peer's annotation. DeepInfra and Mistral use temperature 0 and top-p 1; Mistral uses high reasoning effort and standard-only service. Exact request bodies and parameters are retained privately.

Each request makes one bounded HTTP dispatch to its fixed provider endpoint. Redirects, invalid UTF-8, duplicate JSON keys, wrong model identities, unsupported response shapes, tool calls, inconsistent usage and unknown finish reasons are rejected. A fully received invalid UTF-8 or JSON body is not retried. Error messages and headers are not copied into records. Retained HTTP error bytes have a SHA-256 digest. Credentials are supplied through secrets; detected literal, JSON-escaped and base64 echoes, including the first or last 16 credential characters, suppress the retained body. This filter does not claim to detect every possible transformation of a secret.

Completed empty, whitespace, refusal and output-limited responses retain their raw content and finish reason. They are never retried to obtain a better answer. A technical error retains available partial bytes separately and receives no semantic judgment. One eligible technical retry occurs after the planned first pass, with the same input and trial identity. A completed invalid judge output stays rejected; there is no automatic repair prompt.

HTTP response bodies are bounded to 16 KiB for the respondent and 128 KiB for judges and preflights. An oversized body retains only a safe bounded prefix as technical evidence. Judge reasons are limited to 1000 UTF-16 code units and excerpts to 512, as stated in the judge instruction. These bounds limit accumulated campaign memory; they do not truncate an accepted response or annotation.

## Durable execution and budget

Cloudflare Workflows caches bounded steps; its automatic retries are disabled. R2 stores immutable inputs, requests, outcomes, annotations and journals. A conditional-write budget ledger covers all three providers. Before HTTP, it reserves a conservative full-context input bound plus the output ceiling, using exact decimal arithmetic rounded upward. Verified usage settles to a conservative price-based upper bound. Unknown cost retains the whole reservation. These amounts are not invoices.

A reservation without a retained outcome cannot be dispatched again under the same attempt identifier. An outcome retained before a crash can be settled without sending again. Storage failures, expired authorization or an exhausted budget stop execution. Three technical smoke requests, one per model, run before the 560 trials and use the same ledger. A failed smoke stops the campaign.

Before any provider call, a cached Workflow step verifies create-only writes, rejection of a stale etag and acceptance of the current etag against the actual campaign bucket. An interrupted qualification stops execution. An immutable `budget-started.json` marker must also be durable before dispatch; if the mutable ledger later disappears, that marker prevents recreating an empty budget. Neither the runner nor this delivery deletes either record.

The respondent smoke requests `OK`. Each judge preflight evaluates a fixed empty-response fixture and must produce a valid rubric annotation. These are technical qualifications, excluded from the 560 observed responses and the scientific annotations. The packet also pins provider token-count observations covering all 56 distinct respondent prompts before their ten repetitions; observed counts are distinct from the conservative spending reservation.

The respondent transport allows 90 seconds and each judge transport allows 300 seconds, including their native preflights. Workflow steps allow six minutes and no automatic retry. Each attempt records its elapsed time and timeout. A preflight using at least 80% of its timeout stops before the scientific trials. Later timeouts remain uncertain spending and can still stop the campaign before completion; the ceiling is never relaxed to complete it.

After all three native preflights, the runner retains their latencies and a latest scientific start time. Its scheduling allowance is three times the planned response count times the sum of the three preflight latencies (at least one second each), plus thirty minutes. It stops before scientific dispatch if that allowance would exceed `expiresAt`. This conservative planning estimate is not a guarantee that full responses or reasoning judgments will finish within the window.

The execution packet pins the source commit, Worker bundle hash, all nine protocol inputs, metadata evidence, price verification time, owner authorization and two deadlines. Metadata, token counts and prices must be at most 72 hours old before `admitBefore`. The durable admission step retains its timestamp; replay validates the immutable snapshot at that original instant. The separate `expiresAt` deadline, at most seven days after `admitBefore`, forbids new reservations when reached. It is a hard execution limit, not a promise of completion. The packet is immutable after launch. A corrected packet needs a distinct campaign identity; changing stored bytes cannot silently resume the original campaign. A new identity never renews the shared USD 50 grant after any billable or uncertain attempt.

`scripts/prepare-pilot.mjs` prepares the private packet offline from those reviewed inputs. It neither uploads nor calls providers. Output must be outside the public package, and the destination must not already exist. Its arguments are `--campaign`, `--preflight`, `--token-measurements`, `--bundle`, `--source-commit`, `--admit-before`, `--expires`, `--pricing-verified`, `--authorization` and `--output`. Preparation validates the packet but does not independently certify its metadata or authorize a launch.

The production plan must explicitly configure the Workflow subrequest allowance, which includes R2 operations as well as provider HTTP. The default 10000 allowance is insufficient: a normal durable attempt uses eleven subrequests before journals and annotations, with extra reads for initial ledger creation. The first-pilot plan uses 150000; the conservative calculation including up to seven conflicts in each ledger update is below 142000. This platform allowance does not increase the 3366-attempt or USD 50 provider limits. Effective account and deployment limits require verification before launch.

## Judgments and reporting

The two original annotations remain separate. The validator enforces applicability, exact response excerpts and empty-response precedence. Descriptive counts retain case, language, condition, dimension and reviewer, including valid unpaired annotations. `evaluable` means PASS or FAIL for that applicable dimension; `notEvaluable` means UNSCORABLE. Missing judgments and NOT_APPLICABLE are separate. No single global evaluability or quality score is invented.

An explicit inventory of completed responses defines the judgment population. `planned` and `notReceived` remain visible in every stratum; `expected` counts only received responses. Technical-only trials are excluded from judgment denominators and `missingPairs`. Received replies with missing or rejected annotations remain judgment gaps. No annotation may refer to a trial outside the completed-response inventory.

`rejectedJudgments` is an attempt history: it includes transient errors subsequently recovered by the one permitted retry. It is not a count of final missing judgments; use `missingPairs` and the per-reviewer missing counts for that purpose. Empty-response precedence follows JavaScript `trim()`; invisible characters such as U+200B do not become empty automatically and remain subject to the semantic rubric and the two independent judges.

Agreement uses paired annotations only, with contingency tables, margins, observed agreement, expected agreement and Cohen's kappa before arbitration. Kappa remains null when no pair exists or expected agreement equals one. Missing or rejected annotations are not imputed. Trial metadata preserves case/language/repetition pairing across conditions. Seven cases in one fictional service do not establish general architecture superiority or a verifier effect.

## Private operations and evidence

The Worker has no public route or workers.dev exposure. Its service-bound `/internal/pilot-status` reader exposes only pinned campaign identity, Worker version, attempt counts, budget reservations and activity time. The serving version must match the retained execution identity once work has begun. The Observatory consumes this aggregate through a private service binding and its existing Access controls. It rejects a different campaign, manifest or deployed Worker version. Thirty minutes without recorded activity is reported as stale; this is an activity check, not proof of the Workflow's control-plane state. The Observatory's `verified` label means that the aggregate contract passed, including a valid stale campaign state; it is not a health or completion verdict.

Raw prompts, responses and judgments remain in private R2 and private Workflow step state. No automatic deletion, public raw-data export or email alert is enabled by this runner. Workflow retention follows the platform configuration; R2 evidence is retained until a separately authorized retention action. Final evidence must distinguish local tests, real provider observations, code deployment, campaign progress and completed analysis.
